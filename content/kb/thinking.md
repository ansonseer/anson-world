# Thinking — mental models

> 每个 model 未来是一个"房间"：不是一句 quote，而是"这个判断是怎么形成的"。每条需要一个真实出处故事（form: 场景 → 撞墙 → 规则成形）。

## 1. Source Truth
Truth lives between perspectives. The manager, the worker, the customer and the system each hold a different version; none of them is lying, and none of them is right. Walk into the operation and reassemble it yourself.

## 2. Build after observing
Don't build from the job description of a problem — build from watching the problem happen. Shoe Locator existed because I stood in the aisle, not because someone wrote a spec.
- Origin story: warehouse floor (link timeline.md). [FILL: 补一句当时观察到的具体断点]

## 3. Trust > Capability（"谁替你说话"）
Deals close on trust, not on demos. Capability is table stakes; the thing being bought is confidence that you'll still be honest when it breaks.
- Origin story（已确认，Ao 2026-09-04 原话）：Shoe Locator V1 技术上就成立，但没人替它说话，于是它躺了几个月。第二次我没找老板，先让带教主管上手，由他向老板说明——付费试点当场获批。**中小企业的采用决策不由技术优劣决定，由"谁替你说话"决定。**

## 4. Simple is client-defined
"Simple" means simple for the person using it, not simple in the architecture diagram. If the client needs a manual, it isn't simple yet.

## 5. Distribution > another demo
One more demo changes nothing; one indexable, findable artifact compounds. Make one thing, echo it through five channels. (This site is that rule, applied to myself.)

## 6. Honesty as aesthetic
Status badges that say "never deployed" out loud. The fact record (facts.md) as product surface, not fine print. In a market of inflated claims, verifiable honesty is differentiation, not weakness.
